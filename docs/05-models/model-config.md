# models 与 additionalModels

[返回首页](../../README.md) · [本分类目录](README.md)

解释固定模型列表为何会影响自动发现。

执行位置：**配置说明** · 分类：模型与服务商

模型列表可能同时受到 Codex 的模型发现、Paseo 提供方设置和自定义配置影响。刷新不能绕过一份已经固定下来的列表。

| 配置概念 | 作用 | 适合场景 |
| --- | --- | --- |
| 自动发现 | 由当前提供方和相关 CLI 返回模型信息 | 希望随后端能力显示模型 |
| models | 指定固定的模型列表，覆盖自动发现列表 | 有意限制或完全接管显示模型 |
| additionalModels | 在已有模型来源上补充条目 | 保留自动发现，同时加入额外 Model ID |

## 刷新无效时的检查顺序

- 先确认正在检查的是远程 Linux 主机对应的提供方配置。
- 查看是否曾手工设置过 models 固定列表。
- 仅想补充模型时，优先使用支持该能力的“添加 Model”入口。
- 如需手工编辑，先备份当前配置，并按安装版本的配置文档确认字段位置和结构。
- 改动后重新检查 provider models，并发送一次最小模型请求。

> **不直接粘贴配置片段**
>
> 字段应放在哪一级、模型对象需要哪些属性，取决于当前配置结构和版本。本页解释两者区别，避免把示意字段直接粘贴到错误的位置。
